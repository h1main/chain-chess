# 连锁棋 Chain Chess

`Chain Chess 1.0 beta1` 是一个基于浏览器的多人实时连锁棋游戏。玩家通过房间进行联机对局，服务端使用 WebSocket 同步棋盘状态，支持多人设备、单设备多玩家和观战。

本版本的设计重点是：规则简单、反馈清晰、连接稳定，不保存长期存档。

## 功能

- 多人实时房间对局
- 一台设备控制多个玩家
- 首轮自由落子，按首轮实际落子顺序确定后续回合
- 连锁爆裂与玩家淘汰
- 观战模式
- 对局结束后查看复盘
- 复盘支持上一步、播放、下一步
- 连锁动画期间禁止重复操作
- 当前设备玩家、当前回合、网络状态和玩家状态提示
- 玩家颜色、在线状态、淘汰状态显示
- 所有玩家主动退出后删除房间
- 所有玩家断线超过 5 分钟后自动清理房间
- 房间和复盘只保存在服务端内存中

## 游戏玩法

### 目标

通过落子和连锁爆裂扩大自己的棋子范围，淘汰其他玩家，成为棋盘上最后仍拥有棋子的玩家。

### 首轮落子

1. 游戏开始后，每位玩家各落子一次。
2. 首轮不预设玩家顺序。
3. 玩家第一次实际落子的先后顺序，会成为之后的回合顺序。
4. 首轮落子时，与已有棋子曼哈顿距离不超过 2 的位置不能落子。
5. 首轮完成前不会进行淘汰判断。

### 普通回合

- 轮到玩家时，只能在自己的棋子上落子。
- 每次落子会使该格棋子数量增加。
- 普通回合不能在空白格直接创建棋子。
- 如果当前设备控制多个玩家，系统会自动选择当前轮到的本设备玩家。

### 连锁爆裂

- 当一个格子的棋子数量达到 4 个时，该格会爆裂。
- 爆裂会清空原格，并向上、下、左、右四个相邻格传递棋子。
- 相邻格会归属当前爆裂玩家，并增加棋子数量。
- 新增的棋子可能继续触发爆裂，直到棋盘稳定。
- 连锁过程中棋盘会暂时禁止点击，避免重复请求。

### 淘汰与胜利

- 一个玩家完成过落子后，如果棋盘上不再拥有自己的棋子，则被淘汰。
- 被淘汰玩家不能继续进行普通回合。
- 棋盘上只剩一名玩家拥有棋子时，对局结束。
- 对局结束后显示获胜玩家，并开放复盘功能。

## 房间与设备

### 创建房间

创建者需要设置：

- 房间名称
- 可选房间密码
- 棋盘大小
- 对局总玩家数
- 本设备共同操作的玩家数
- 本设备名称

### 加入房间

加入者可以选择本设备控制的玩家数量。一个设备可以控制多个玩家，但房间的总玩家数量仍由创建者决定。

### 观战

观战者不占用玩家席位，也不需要填写玩家数量和玩家名称。观战者只能查看实时棋盘，不能落子。

### 数据生命周期

本版本不使用数据库，不保存长期存档：

- 房间状态只保存在 Node.js 进程内存中。
- 服务重启后，所有房间和对局数据都会丢失。
- 所有玩家主动退出后，房间立即删除。
- 所有玩家断线超过 5 分钟后，服务端自动删除房间。
- 复盘只在当前对局结束后可查看。

## 技术结构

```text
浏览器
  ├─ HTTP / HTTPS：加载游戏页面
  └─ WebSocket / WSS：同步房间和棋盘状态
          │
          ▼
Node.js + ws
  ├─ 房间管理
  ├─ 游戏规则
  ├─ 连锁动画状态同步
  └─ 临时复盘数据
```

## 本地运行

要求：Node.js 20 或更高版本。

```bash
npm install
npm start
```

默认地址：

```text
http://127.0.0.1:8080
```

指定监听地址和端口：

```bash
HOST=0.0.0.0 PORT=8080 npm start
```

Windows PowerShell：

```powershell
cd E:\chain-chess-1.0beta1
npm install
$env:HOST="0.0.0.0"
$env:PORT="8080"
npm start
```

## Ubuntu 部署

建议让 Node.js 只监听本机 `127.0.0.1:8080`，由 Nginx 对外提供域名、HTTPS 和 WebSocket 转发。

Node 服务启动命令：

```bash
HOST=127.0.0.1 PORT=8080 npm start
```

Nginx 需要同时转发网页和 `/ws` WebSocket 路径：

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 3600;
}
```

使用域名和 HTTPS 后，浏览器会自动将 WebSocket 连接切换为 `wss://`。

## 端口

生产环境通常只开放：

```text
22/tcp   SSH
80/tcp   HTTP、证书验证和跳转
443/tcp  HTTPS 与 WSS
```

不建议将 Node.js 的 `8080` 端口直接暴露到公网。
